# Diagnostice de randare (PBI019)

Composition root conectează `diagnoseBackend` și `createDiagnosticsPanel` după crearea backendului. Panoul este separat de HUD; închis implicit. Deschiderea activează colectarea, închiderea o oprește și golește istoricul. Nu există al doilea RAF sau setInterval: refresh este apelat din renderul deținut deja de lifecycle și verifică propriul gate de minimum200ms. Numai câmpurile modificate primesc scrieri DOM. Un panou închis nu agregă și nu scrie în DOM.

`DiagnosticsCollector` are ring numeric fix, implicit240samples, configurabil1..4096. Patru canale Float64 (CPU render, interval cadru, GPU și CPU tick) folosesc240×32=7680bytes; record este O(1), fără sortare, coadă sau istoric nelimitat. `report()` copiază/sortează cel mult capacitatea per canal și întoarce p50/p95/p99 și numărul de samples disponibile. Datele lipsă sunt null; zero este acceptat numai ca valoare măsurată. Dezactivarea golește ring-ul, iar reactivarea pornește un interval nou.

`diagnoseBackend(backend, options?)` întoarce wrapperul `backend`, colectorul, `setEnabled`, `report`, `dispose`. Deține numai instrumentarea, nu simulează. `dispose()` curăță diagnosticele; `adapter.backend.dispose()` curăță apoi backendul original. Un singur adaptor de diagnostice trebuie să dețină instrumentarea unui engine. `now`, `counters` și `tickCpuMs` sunt porturi opționale injectate.

CPU render este timpul sincron al backend.render, incluzând beginFrame/scene.render/endFrame. Intervalul frame este timpul dintre începuturile renderurilor; nu este timpul CPU. Raportul nu le adună cu GPU. GPU folosește EngineInstrumentation și query extensions publice din Babylon9.29.0: capabilitatea timerQuery trebuie să existe și counter.count trebuie să crească înainte de admiterea unui rezultat nou. Primul rezultat după activare este omis pentru a evita un query întârziat din sesiunea precedentă. Valorile nanosecondelor Babylon se convertesc în milisecunde. Rezultatele sunt asincrone și nu sunt atribuite artificial cadrului curent; samples pending/unsupported sunt null, cu status explicit. Instrumentarea poate lipsi pe un backend/dispozitiv fără query. Timpul GPU nu este FPS și nici memorie GPU.

SceneInstrumentation oferă draw calls; contoarele scenei oferă meshes/nodes/materials/textures/geometries. Acestea sunt obiecte deținute de Babylon, nu RAM/GPUbytes exacte. Dezactivarea oprește timer queries și elimină instrumentarea; observerul scenei și instrumentarea sunt eliberate idempotent la shutdown. Backendul deține orice resursă engine până la propriul disposal.

În bootstrap, tick și debt citesc starea reală a buclei008. CPU tick complet, bytes în așteptare, joburi, entități, profil și worker sunt null până când serviciile relevante furnizează contoare efective. Nu se raportează drept joc măsurat valoarea sintetică din fixture. Pentru021/218, portul tickCpuMs trebuie să primească timpul întregului tick autoritar, incluzând pregătirea/comenzile și snapshoturile relevante; timpul unui callback gol nu îl înlocuiește. CPU total al colectorului/panoului este măsurat separat în proba enabled/disabled.

Inspectorul este încărcat la apăsarea butonului disponibil doar în DEV. `showDevelopmentInspector` verifică guardul compile-time, importă din devDependency9.29.0 și reverifică scena după import. API-ul modern ShowInspector/token este deținut într-un WeakMap; deschiderea repetată reutilizează ownerul activ și adaugă cel mult un observer de cleanup per scenă. Scena disposed nu poate fi deschisă după un import întârziat. În producție nu există butonul, importul inspectorului sau codul debug nefolosit în aplicație. Politica arhitecturală și buildscan verifică această excludere efectivă.

Probe: `node scripts/build-diagnostics-fixture.mjs before|final|development` construiește fixture-uri congelate în directorul ignorat `.pbi-validation-019`, pentru Vite preview fără HMR. `development` este un build explicit de validare cu DEV=true, neminificat; nu este distribuția de producție. `/tests/browser/diagnostics/` expune `bootstrapProbe` și `diagnosticsProbe('WEBGL2'|'AUTO', keep?)`. Proba compară colectarea disabled/enabled cu panoul deschis la5Hz, raportează render+colector și costul UI separat, ring/cleanup și proiecții explicit sintetice. `scripts/verify-diagnostics-build.mjs` verifică sourcemap sources din aplicația produsă, fixture-ul final și cel DEV.

[Dovezile](Evidence/019-diagnostics/report.md) păstrează rezultatele, baseline-ul și limitările. Bugetele sunt provizorii înainte de203; aceste scene mici nu închid gate-ul de performanță al gameplay-ului.
