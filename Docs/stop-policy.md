# Stop policy 051 — full, rolling and leader-held stops

Status: implementation with targeted local validation. PBI051 board state and publication are owned by the parent; the cost/memory probe, tests and limitations are recorded in [the 051 evidence](Evidence/051-stop-policy/README.md).

`projectStopProfile` reads only the three051 keys (`stop_full_probability`, `stop_dwell_time`, `stop_line_offset`) from an already published profile through the existing registry, with units probability/s/m. It grants no estimator capability and re-validates the supplied values inside `evaluateStopPolicy`, so a forged or out-of-range profile is rejected rather than trusted.

The input schema is sessionId, worldEpoch, actor, decisionTick, seed, profile, observation and leaderStop. The observation is the authoritative037 view of the current opportunity: version, units, tick, opportunityId, stopLineId, distanceToStopLineM (front datum, positive before the line), speedMps, stationaryDurationS (the continuous authoritative stationary proof in seconds, null while a full stop is unproven) and crossed. `opportunityId` is the037 STOP_APPROACH identity, so the compliance sample `randomUnit(deriveOpportunitySeed(vehicleSeed, opportunityId), 'full-stop', 0)` is drawn once per identified opportunity and re-evaluating it never re-samples.

Below `stop_full_probability` the sampled role is FULL: the policy requests the stop (`STOP_APPROACH` while `distanceToStopLineM - stop_line_offset > 0`), holds at the stop point without a proof (`STOP_HOLD`), holds while the authoritative duration is below `stop_dwell_time` (`DWELL_IN_PROGRESS`) and releases only when the duration reaches it (`DWELL_SATISFIED`, inclusive comparison). At or above the probability the sampled role is ROLLING: the decision declares its intent (`ROLL_THROUGH`/`ROLLING_STOP_BY_PROFILE`) and never waits for a full-stop proof, so prudent and rolling profiles produce distinct observed outcomes without any hidden style clamp. A crossed line releases (`STOP_LINE_CROSSED`). Because the037 producer owns the proof window, the owner must configure it with a minimal dwell so the configured `stop_dwell_time` remains resolvable; the policy compares the reported duration and never re-derives stationarity itself.

The two evidence paths stay separate. `leaderStop: LEADER_OR_QUEUE` is an independent input describing a leader/queue hold; when no STOP opportunity exists the decision is `NO_STOP`/`LEADER_STOP_NOT_STOP_INTENT` with `leaderInduced: true` and no requested stop, so045 keeps FOLLOW/FOLLOW_LEADER. A real STOP observation alongside a leader hold still reports the driver's own intent, and `stopBehaviorFacts` only raises `stop: STOP_RULE_BY_PROFILE`, preserves an existing red fact, clears only its own fact on release and is fenced by exact version and profile version. A missing profile or a stale/future observation yields `UNKNOWN` with no fabricated facts.

Admission bounds:110 actors per packet, six-tick observation age,256/128 UTF-16 units for identities and profile version, distances within ±1000 m, speed0–100 m/s, durations0–60 s, zero retained actors/opportunities/history. Rejection is atomic; no accessor is invoked and no history is retained.

Evidence at commit `8059f60d`: 832 project tests pass, the six051 tests cover a free STOP (approach, hold at the applied offset, dwell in progress, release at exactly the configured duration and with a longer requirement), prudent versus rolling profiles with one sample per opportunity, a leader-induced hold that never becomes STOP intent (including the real045 owner staying in FOLLOW_LEADER), crossing, red precedence and strict admission. A real037 drive proves the emitted STOP_APPROACH/FULL_STOP/STOP_LINE_CROSSED evidence, the dwell-bound release and that a requirement above the observed proof never releases. The targeted native probe measures the added cost on the real037/045 fixture: p95 `+0.0141 ms` per10 Hz decision with five preserved repetitions. See [the evidence](Evidence/051-stop-policy/README.md) for the manifest comparison and the ownership counters.

Limitations: the current stationary duration of an opportunity is the owner's authoritative readback of the037 stream (037 publishes the proven full stop, not the running duration); the affected object/route/bus ownership stays outside this module. No browser, GPU, FPS or integrated-game acceptance is claimed, and the calibration labels remain provisional.
