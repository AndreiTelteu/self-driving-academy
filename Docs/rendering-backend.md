# Bootstrap de randare implementat (PBI011)

`createRenderingBackend(canvas, preference)` este asincron, exportat din `src/rendering/babylon`. Preferințele sunt `AUTO`, `WEBGPU`, `WEBGL2`, aceleași valori ca `QualityPreferences.preferredBackend`. `AUTO` și `WEBGPU` preferă WebGPU și permit fallback; `WEBGL2` sare peste WebGPU. Backendul expune `rendererKind`, `scene`, `canvas`, `render()`, `resize()`, `dispose()`.

Canvasul transmis este un punct de montare. Fiecare tentativă îl înlocuiește cu un canvas nou cu aceleași atribute; apelantul folosește `backend.canvas` după succes și regăsește canvasul din host la retry. Nu se păstrează listeners pe canvasul vechi. Tipul unui context canvas nu poate fi schimbat, inclusiv după disposal; [contractul browserului](https://developer.mozilla.org/en-US/docs/Web/API/HTMLCanvasElement/getContext) impune această înlocuire.

WebGPU folosește `WebGPUEngine.IsSupportedAsync` și `initAsync()`. Compilatoarele JS/WASM glslang și twgsl sunt importate prin URL-uri Vite din pachetul local Babylon **9.29.0** și emise în build; nu se configurează CDN. Sunt încărcate de Babylon la necesitatea traducerii shaderelor, nu de scena bootstrap goală. [Documentația oficială](https://doc.babylonjs.com/setup/support/webGPU/) și declarațiile/sursa versiunii instalate au fost verificate. WebGL2 cere direct `canvas.getContext('webgl2')`, pasează acel context către `Engine`, apoi verifică `engine.webGLVersion === 2`; nu permite fallback implicit la WebGL1.

Scena și engine-ul tentativei sunt deținute înainte de orice pas asincron. Eșecul inițializării scenei eliberează scena, engine-ul și canvasul, apoi construiește alte resurse pentru fallback. În 9.29, `WebGPUEngine.dispose()` dereferențiază helperi care nu există după eșecul requestAdapter/requestDevice. Adaptorul tratează explicit inițializarea parțială prin cleanup common/base și resursele GPU deja dobândite; această porțiune trebuie reverificată la schimbarea versiunii Babylon. Contextul WebGL2 deținut este pierdut explicit prin extensia standard disponibilă; canvasurile sunt reduse la 0×0. `dispose()` este idempotent; render/resize după disposal sunt no-op.

`createRenderingLifecycle` gestionează LOADING → READY/ERROR, un singur frame programat și o subscripție resize. Retry-urile concurente sunt reunite. Disposal în timpul inițializării eliberează backendul primit ulterior. Cleanup încearcă fiecare owner, inclusiv dacă alt cleanup aruncă, fără să blocheze starea recuperabilă. UI are mesaje live, `aria-busy`, alertă la eroare și buton nativ „Reîncearcă”. Setările și datele locale nu sunt șterse. Exporturile locale nu au încă UI/serviciu de export în proiect; nu se inventează unul în acest PBI.

Scena bootstrap conține numai o cameră fixă pentru a putea randa cadrul de clear. Nu implementează camere de vehicul, gameplay, registry, device-loss recovery complet sau limitele grafice ulterioare. `createApplication` și rendererul metadata bootstrap rămân disponibile pentru probele inițiale de injecție/lifecycle fără GPU; aplicația browser folosește acum lifecycle-ul asincron.

## Verificare

Teste pure ES2022: `node --import ./scripts/register-typescript.mjs --test tests/rendering/*.test.ts`. Fixture browser: `/tests/browser/rendering/` pe Vite; exporturile `runProbe(mode, cycles)` și `startRetryProbe()` se execută în T3 preview. Fault injection există numai în fixture, nu în aplicația distribuită. [Dovezile](Evidence/011-render-boot/dovezi.txt) disting succesul real WebGPU/WebGL2 de indisponibilitate/eșec injectate. Contoarele verifică ownership, nu memoria GPU exactă. Nu se declară FPS, bugetul jocului complet sau hardware de referință din aceste probe.
