# Lane-change policy 053 — optional pass with latched continuity

Status: implementation with targeted local validation. PBI053 board state and publication are owned by the parent; the cost/memory and grouped probes, tests and limitations are recorded in [the 053 evidence](Evidence/053-lane-change/README.md).

`projectLaneChangeProfile` reads only the four053 keys (`lane_change_front_gap`, `lane_change_back_gap`, `lane_change_speed_gain`, `lane_change_cooldown`) from an already published profile through the existing registry, with units m/m/m/s/s, and re-validates them inside `evaluateLaneChange`. It grants no estimator capability and no hidden style limit.

The input schema is sessionId, worldEpoch, actor, decisionTick, profile, state, adjacency, observation, speedMps, ownLaneLeaderSpeedMps and intent. `adjacency` is an explicit projection authored by the033 graph owner (version, mapId, currentLaneId, access and at most two lateral neighbours with their side); the policy never derives a lateral edge itself and refuses a target that the projection does not expose, including through the access class, which is how the033 access semantics are honoured. `observation` is the target-lane view at a tick: coverage (`COMPLETE` or `LOCAL_ONLY`), the nearest front and back gaps (null asserts an observed clear lane) and `targetLaneSpeedMps`, the achievable speed in that lane. LOCAL_ONLY coverage is refused so a local query can never certify a horizon-wide gap.

A fresh optional change requires, in this order: an explicit `OPTIONAL_OVERTAKE` intent, complete coverage, no active cooldown, at least `lane_change_front_gap` of front gap, at least `lane_change_back_gap` of back gap and a speed advantage of at least `lane_change_speed_gain`. The advantage is `targetLaneSpeedMps - min(speedMps, ownLaneLeaderSpeedMps)`, so an own-lane leader makes the same target lane attractive while a fast target lane alone does not. The cooldown is `ceil(lane_change_cooldown * 60)` ticks against the latched last change tick, inclusive at the boundary.

Continuity is explicit and caller-held. `LaneChangeState` carries the committed manoeuvre (target lane plus its start tick) and the last change tick; it is supplied in the input and returned in `decision.state`, so the owner carries it forward every frame. While a manoeuvre is committed the policy keeps reporting `CHANGE`/`COMMITTED_CONTINUITY` from the latched target lane without re-reading the start gates, so failing gaps or an active cooldown cannot reset it mid-manoeuvre. The manoeuvre is released explicitly when the committed lane is no longer an authored lateral neighbour (for example because the vehicle now occupies it), which clears only the commitment and preserves the cooldown. `laneChangeBehaviorFacts` raises `laneChange: VALIDATED` for045 (`CHANGE_LANE`/`LANE_CHANGE_VALIDATED`), clears only its own fact otherwise and is fenced by exact version and profile version; a missing profile, a missing adjacency or a stale/future observation yields `UNKNOWN` with no fabricated fact.046 keeps the cruise reference on CHANGE_LANE, so a validated change never zeros the style target.

Admission bounds:110 actors, at most two lateral neighbours, six-tick observation age,256/128 UTF-16 units, gaps0–10000 m, speeds0–100 m/s, cooldown up to1800 ticks, zero retained actors/manoeuvres/history. Rejection is atomic and does not invoke accessors.

Evidence at commit `8059f60d`: 832 project tests pass, the nine053 tests cover an insufficient front gap and an insufficient back gap staying in lane, an absent speed advantage staying in lane, two changes too close being blocked by the inclusive cooldown (including a shorter configured cooldown), a started manoeuvre keeping continuity across five cadence decisions with failing gates and an active cooldown, explicit release when the target lane is no longer a033 neighbour, the real033 access filter, an invented edge being refused and the real045 composition. The219/033/046 chain additionally proves the cruise reference is preserved on CHANGE_LANE. The targeted native probe measures the added cost on the real033/045 fixture: p95 `+0.0121 ms` per10 Hz decision with five preserved repetitions; the grouped probe reports p95 `+0.0180 ms` for all three policies together. See [the evidence](Evidence/053-lane-change/README.md).

Limitations: the lateral adjacency is the owner's033 projection and the manoeuvre latch plus its completion are explicit caller decisions, so unsupported lateral geometry is reported as a missing/foreign fact rather than an invented edge; the optional change is not a route-required manoeuvre. No browser, GPU, FPS or integrated-game acceptance is claimed, and the calibration labels remain provisional.
