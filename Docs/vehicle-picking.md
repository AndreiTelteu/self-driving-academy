# Selectarea vehiculelor (PBI018)

Pickingul este o compoziție explicită de prezentare: `VehiclePickingRegistry(scene)` păstrează identitatea, `BabylonVehiclePicker(scene, registry)` face query-ul Babylon, iar `bindVehiclePickingInput(options)` traduce un click pe canvas în `{ type: 'SELECT_VEHICLE', entityId }`. Callbackul `onSelect` livrează intenția callerului; acesta poate actualiza vehiculul urmărit de camera017 și UI. Nu există comandă MANUAL, modificare de VehicleCommand, tick sau corp fizic. Selecția din lista flotei poate folosi direct același ID, fără picking.

Registry-ul poate primi `entityIdFor: node => sceneAdapter.entityIdFor(node)` pentru reprezentările013. `register(root, entityId)` acoperă descendenții; o instanță obișnuită se înregistrează separat dacă nu are acel root. Identitatea nu se deduce din numele meshului, ordinea listei de vehicule ori metadata externă.

`registerThinBatch(mesh, entityIds)` copiează și îngheață tabelul complet index→entityId. Un element null înseamnă geometrie fără vehicul. Lungimea trebuie să fie exact `thinInstanceCount`; după fiecare reorder/removal callerul actualizează matricile și tabelul în aceeași operație sincronă, înaintea următorului input. La schimbarea numărului fără remap pickingul refuză tabelul vechi, în loc să aleagă alt vehicul. Reordonarea de matrici cu același count nu poate fi descoperită automat: remapul explicit rămâne obligatoriu. Un thin hit nu moștenește ID-ul hostului013. Registry-ul activează thin-instance picking și restaurează valoarea precedentă la unregister/dispose.

Capacitățile implicite sunt 4.096 bindings și 65.536 identități thin cumulate în registry; opțiunile pot fixa alte plafoane. Datele se validează înainte de înlocuire, astfel încât un remap invalid păstrează mappingul valid. Node-uri foreign/disposed sunt respinse. Dispose-ul unui node elimină bindingul, iar dispose-ul registry-ului scoate toți observerii fără a distruge meshurile callerului.

Pickerul acceptă coordonate în pixeli ai rezoluției interne. Adaptorul de input convertește clientX/Y din bounding rect CSS, inclusiv resize/DPR/scalare. Pickerul convertește mai departe convenția hardwareScalingLevel a Babylon. Query-ul returnează cea mai apropiată suprafață pickable, fără fastCheck: decorul neînregistrat din față produce null, nu click prin obstacol. Decorul exclus intenționat de caller prin isPickable=false nu blochează selecția. Vizibilitatea/pickability sunt ale reprezentării Babylon, nu un filtru care scoate vehiculul din simulare.

O scenă are un singur owner `BabylonVehiclePicker`. Acesta dezactivează pickingul automat Babylon la pointermove/down/up. Dispose-ul restaurează flags încă deținute de owner, apoi permite reconstrucția pickerului. Nu adaugă observatori per frame ori o buclă de randare. Fără `onHover`, 1.000 pointermove nu produc niciun scene.pick; cu `onHover` fiecare mișcare eligibilă cere explicit query. Hover-ul trebuie activat numai în fluxul care îl folosește.

Inputul este legat exclusiv de canvas. UI peste canvas primește evenimentul pe propriul element. `isModalOpen()` este verificat înainte de gest și înainte de click; un modal deschis consumă clickul pe canvas prin preventDefault/stopImmediatePropagation, fără query. `enabled()` permite blocarea inputului în loading/pauză etc. Pointer lock al camerei împiedică selecția accidentală. Dragurile peste 5 px, pointercancel, blur, clickurile secundare și clickurile prevenite sunt ignorate. `maxDragPx` este configurabil. Babylon poate preveni pointerdown/up pentru camera sa; acestea nu anulează selecția. Eliberarea normală a capturii după pointerup păstrează clickul, iar pierderea capturii în mijlocul gestului îl anulează. Clickul final respectă defaultPrevented. Cleanupul idempotent elimină toate listeners.

Compoziția reproductibilă este [fixture-ul browser](../tests/browser/vehicle-picking/index.html): taxi normal, civil instance, două vehicule thin, decor occluder și UI/modal. [Dovezile](Evidence/018-vehicle-picking/verification.md) separă baseline-ul existent, costul query-ului nou, probele WebGL2/WebGPU și clickurile reale. Bootstrapul aplicației încă nu compune vehicule de gameplay; integrarea se face când lumea și vehiculele există, în aceeași buclă de prezentare.
