# 080 key remapping report

Machine-readable transcript: [report.json](report.json). Generated by `npm run key:remapping`; it
contains no wall-clock value, random value or browser-only state.

Version: `080-key-remapping-v1`. The report drives the real `createKeyRemappingPanel` adapter, the pure
draft operations and the 009 `SettingsStore` composition over deterministic inputs. A synthetic
keydown is an adapter test, not a trusted browser capture.

## Contract

Actions: throttle, brake, steerLeft, steerRight, handbrake, manualMode, learningMode, kpis, fleet, signalLeft, signalRight, camera, profile, pause, recover.

Critical actions: throttle, brake, steerLeft, steerRight, handbrake, manualMode, learningMode, pause, recover.

States: VALID, CONFLICT, UNSUPPORTED, UNCHANGED. Rejections: UNSUPPORTED_CODE, MODIFIER_ONLY, RESERVED_BROWSER_CODE, EMPTY.

Reserved browser codes: F1, F3, F5, F6, F7, F10, F11, F12. Modifier-only values: Shift, Control, Ctrl, Alt, AltGraph, Meta, OS, Super, Hyper, Fn, FnLock, CapsLock, NumLock, ScrollLock, Symbol, SymbolLock, MetaLeft, MetaRight, OSLeft, OSRight.

Rules: all 15 actions are always listed; an action without a valid code stays visible and invalid; a code bound to more than one action is a conflict and blocks save; reset proposes the real createDefaultSettings bindings locally; save stays explicit; capture consumes only the next keydown on the focused key button; Escape cancels it; bindings are device/settings state, never profile parameters or learned values.
