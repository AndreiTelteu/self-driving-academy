## Ordered observations and bounds

Preallocate numeric arrays before measurement; preserve all 600 ticks in original order. For each tick retain monotonic packet-preparation start/end, controller-call start/end, assertion start/end, and checkpoint/heap-sample start/end when present. Continue physical-port elapsed observations, without claiming marginal phase percentile subtraction gives whole-tick attribution. Align GC entries by actual start/duration intervals with these segments; report overlapping and boundary-spanning events explicitly. Asynchronous delivery is drained outside measurement. GC overlap is temporal association, not proof that a particular call caused collection or that GC duration exactly adds to its call latency.

Keep the same ten raw heap samples at sixty-tick cadence plus immediate unsorted post-loop heap and live post-GC endpoints. Profile samples should expose source stacks for descriptor/schema checks, controller projection/realization, damage identity/read, packet/assertion/trace work, and native bridge where actually sampled. Preserve unexplained/native/unmapped samples rather than attributing them to 029. Also retain process CPU usage and start/end host load/free-memory metadata as observations; they cannot establish frequency or thermal control.

Bound raw GC entries to 4096, tick rows to 12000, CPU samples to 100000 per profiled run, profile nodes to 20000, allocation samples to 100000, and serialized profile output to 32 MiB per run. On unsupported API, overflow, malformed timeline, or failed identity/physical/cleanup guard, preserve a unique failure report and stop. Do not truncate, filter slow ticks, drop an arm, or rerun selectively. The profiling runtime internally owns buffers before the resulting size is inspected; these output limits are not exact inspector peak-memory limits. No full heap snapshot is taken.
