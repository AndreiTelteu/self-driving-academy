# 079 learning notifications report

Machine-readable transcript: [report.json](report.json). Generated by
`npm run learning:notifications`; it contains no wall-clock value, random value or browser state.

Version: `079-learning-notifications-v1`. Adapter: `079-learning-notifications-app-v1`. The report drives the real
`createLearningNotifications` adapter over real 103-style queue outcomes, a real 102-validated
composition and an explicit publication payload.

## Contract

Kinds: ANALYZING, RESULT, NO_CHANGE, INSUFFICIENT_EVIDENCE, ERROR, REJECTED, CANCELLED, INVALIDATED, STALE, PUBLISHED.

Rules: every notification is bound to one segmentId and one jobKey, in the text and data-* attributes. a worker composed candidate is RESULT (Candidat validat, nepublicat), never PUBLISHED. ERROR/REJECTED/CANCELLED/INVALIDATED are non-success and never claim a publication. only an explicit 110 publication payload may say Profil publicat. a late event for another segment/job/epoch/session/world becomes STALE and is never the current result. the same segment/job/kind is deduplicated for a bounded window; at most three rows stay visible. every kind has a visual symbol and text; the sound cue is optional and never the only signal.

Limits: 3 visible rows, 10 Hz write ceiling, 30000 ms dedupe window, 15000 ms lifetime, 4000 ms stale lifetime and 4 missing observations per message.
