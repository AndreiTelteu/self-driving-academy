# Controller comun024

PBI024 implementează `createVehicleController` și portul injectabil `VehicleActuationPort`. Baseline-ul Node BEFORE a fost capturat înainte de implementare, după publicarea028 (`94e1f1c`), și este păstrat în [dovezi](Evidence/024-vehicle-controller/progress.md). Controllerul se compune cu bucla autoritară008; nu introduce un timer propriu.

Controllerul primește un context SI/sessionId/worldEpoch și un port fizic injectat. Tick-ul și dt=1/60 provin din composition root, fără import vehicles→simulation. Modul AUTO autorizează AUTONOMY; MANUAL și LEARNING autorizează PLAYER. Modurile nu schimbă mecanica și nu implementează învățarea. Maximum un vehicul este PLAYER, inclusiv în batchul care eliberează unul și preia altul.

Un pas are trei faze: validare integrală, arbitraj, aplicare fizică o singură dată. Packetul include tokenul BodyIdentity exact și VehicleCommand. Toate câmpurile/world/tick/tokenurile sunt validate înainte de efecte. O comandă malformed sau o comandă de tick greșit invalidează întregul batch; nu se aplică un prefix. Două comenzi ale aceleiași surse pentru un vehicul sunt respinse explicit, inclusiv duplicate identice; nu există last-writer-wins. Un pachet valid dintr-o sursă fără autoritate este raportat ca ignorat și nu acționează. Autoritatea nouă se aplică înainte de selecția comenzii în același tick, astfel încât vechiul AI și noul PLAYER pot apărea în același batch fără anularea preluării.

Ținta AUTONOMY este menținută bounded de la tick-ul livrării până la tick+5 inclusiv. Decizia10Hz se poate reîmprospăta după șase pași; un eveniment urgent poate furniza o țintă mai devreme. Fiecare pas produce o comandă efectivă nouă adresată tick-ului fizic curent, nu reaplică literal un pachet expirat. La expirare se aplică neutru. PLAYER furnizează o comandă pentru fiecare tick; lipsa ei produce neutru. Schimbarea autorității și suspendarea inputului eliberează țintele. Pauza/focusul sunt conectate explicit din composition root și nu au timer ascuns în controller.

Comanda raw rămâne distinctă de comanda efectivă. Dacă brake>0 sau handbrake=true, throttle efectiv este0. Direcția este păstrată. Semnalizarea OFF/LEFT/RIGHT/HAZARD este starea autoritară a comenzii selectate pentru ambele surse, expusă rendererului separat de fizică. O eventuală fază luminoasă se derivă numai din tick, astfel încât pauza nu continuă clipirea.

Portul Rapier primește handbrake opțional (absența păstrează comportamentul anterior). Frâna de mână acționează cele două roți spate cu plafonul per roată deja calibrat021; per roată se folosește maximum dintre frâna de serviciu și comanda handbrake, fără însumare peste plafon. Roțile față primesc numai frâna de serviciu. Această conectare fizică nu declară calibrarea027, ABS, frânare→marșarier sau stabilitatea în viraj implementate.

Readbackul `wheelBrakeImpulseLimitNs` citește cele patru plafoane configurate native, în N·s. API-ul Rapier le numește explicit maximum braking impulse; ele nu reprezintă impulsul realizat efectiv de solver. Distanța și viteza măsurată în scenariul de frânare sunt dovada efectului fizic.

Retenția este maximum110tokenuri active și o țintă/proiecție per vehicul, fără coadă de tick-uri sau istoric. IDs/context vor avea limite explicite înainte de copiere. Refolosirea ID-ului/handle-ului cere tokenul nou; un token din altă lume este invalid chiar dacă valorile coincid. Remove/reset/dispose eliberează starea; epoch-ul nou invalidează întregul context vechi. Tick-ul trebuie să fie următorul tick autoritar, iar apelul repetat nu poate executa fizica de două ori. Dacă portul fizic aruncă după validare, controllerul intră într-un fault terminal, fără retry sau rollback fictiv.

Cele13teste controller verifică aceeași secvență PLAYER/AUTONOMY pe Rapier real pentru ambele clase, takeover în același tick, brake/handbrake, semnalizare, ținte10Hz realizate60Hz la30/60/144cadre, suspend/resume, malformedbatch atomic, duplicate/token/epoch, fault terminal și20cyclescleanup de110mașini/880subscriptions per ciclu. Testele nu substituie verificarea vizibilă din browser.

Probele Node BEFORE/AFTER sunt suplimentare, bounded:70mașini, cinci perechi observer-on/off,180ticks warmup și600ticks măsurați per lume. Toate10checksumuri de input și fizică finală, precum și trace-urile intermediare, coincid exact. Nu se recapturează BEFORE pentru a accepta rezultatul. Se raportează costul incremental al controllerului separat și variația p95; aceasta nu constituie un gate FPS sau o probă a jocului complet. Slotul hardware exclusiv este folosit pentru driving vizibil pe WebGPU/WebGL2, cu focus real și rezoluții CSS/interne1920×1080/DPR1. Raportul identifică sursele, buildul și hardware-ul efectiv. Calibrarea dinamicii, input filtering025, stabilitatea027 și jocul complet rămân în PBI-urile lor.
