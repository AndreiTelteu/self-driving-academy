# Priorități explicite și spații de traversare

PBI038 expune `parseMapPriorityPolicy`, `predictPriorityArrival` și `createPriorityRules`. Modulul world este semantic CPU, independent de Babylon/fizică. Nu comandă frânarea și nu produce recompense, refuzuri juridice sau eligibilitate learning. Dovezile au `learningEligible: null`; callerul decide integrarea viitoare în bus/learning, fără callback ascuns sau variantă nouă în events007.

Harta032 nu are încă prioritate authored. Sidecarul strict conține `schemaVersion: 1`, `units: SI`, `mapId`, `versionId` și reguli `{intersectionId, movementIds: [a,b], priorityMovementId}`. Winnerul este unul dintre cele două IDs sau `null` pentru EQUAL. Parserul validează harta și conflictele geometrice035, cere exact o regulă pentru fiecare pereche incompatibilă și respinge omisiuni, duplicate/reversări contradictorii, referințe străine și perechi compatibile. Nu inferă prioritatea după numele străzii, ordinea arrayului ori o regulă universală a părții drepte. EQUAL rămâne fără obligație de cedare rezolvată. Outputul readonly/frozen se serializează și reparcurge JSON fără câmpuri derivate; relationId este derivat intern din035. Interogarea reciprocă întoarce aceeași regulă.

`observe()` primește observații strict plain schema1/SI cu sessionId, worldEpoch, tick, subject, traffic, trafficComplete și discontinuity. Un actor are vehicleId/incarnation, intersectionId/movementId (ambele cunoscute sau ambele null), speedMps, active/observable și distanțe per relationId. Callerul furnizează distanța semnată autoritară de-a lungul rutei până la intrarea în conflict, în metri; `clearanceM` include lungimea până la ieșirea completă și anvelopa vehiculului. Pozitiv = înainte de intrare, zero = la intrare/ocupare, negativ = după intrare. Aceste date nu sunt estimate din mesh și nu substituie integrarea viitoare cu fizica. Fiecare datum aparține mișcării actorului și politicii validate.

Timpul de intrare și ieșire este distanță în metri / viteză în m/s, rezultat în secunde, cu extrapolare la viteză constantă. Oprirea înainte de intrare are state STATIONARY și timpi null; nu este trafic eligibil care se apropie. Ocuparea, inclusiv staționară, are entry0; exit null înseamnă ocupare fără timp de eliberare cunoscut. CLEARED are ambii timpi null și nu menține o expunere veche. Intervalele de ocupare sunt comparate cu minGapS implicit2 și horizonS implicit10. AVAILABLE descrie numai această predicție locală, nu permisiune de conducere certificată. Pentru subject staționar nu se inventează o accelerație ori un timp de plecare.

Traficul absent și acoperit (`trafficComplete=true`, array gol), inactiv, staționar înaintea intrării ori deja eliberat nu generează dovezi de refuz/cedare. Actorii activi dar neobservabili, ruta necunoscută, distanța lipsă pentru o pereche relevantă, acoperirea incompletă și discontinuitatea produc UNKNOWN, maschează toate gapurile ca UNKNOWN și suspendă dovezile. Perechile cunoscute sunt totuși procesate înainte de mască, independent de ordinea actorilor. Limitele previziunii și traficul neobservabil nu devin drum liber.

Timpul dwell este exclusiv tick/60Hz. Oprirea continuă înaintea intrării (strict distanceM>0, implicit≤3m și speed≤0,01m/s) sub o expunere blocată poate produce o singură dovadă YIELD_OBSERVED după0,25s, fără a atribui motivul opririi. Prima observație începe la0;15 intervale reale produc0,25s. Deplasarea cumulată maximă, luând maximul pe perechi per tick, este0,01m; driftul resetează hold-ul. Un singur hold per vehicul evită multiplicarea dovezilor pentru mai multe perechi/oponenți simultani. Schimbarea setului de conflicte blocante resetează dwell-ul; durata unei expuneri nu este atribuită alteia. La intrare sau în conflict nu se emite dovadă de cedare înainte de intrare.

Traversarea observată CROSSED_WITH_PRIORITY_EXPOSURE folosește două tick-uri consecutive, aceeași incarnation și aceeași bază de rută. Deplasarea subjectului trebuie să fie compatibilă cu maximul vitezelor celor două observații /60 plus toleranța provizorie0,05m; schimbarea clearance-ului sau a rutei produce UNKNOWN. Interpolarea distanțelor semnate găsește momentul intrării chiar dacă vehiculul este deja complet CLEARED în observația curentă. Oponentul prioritar trebuie să fie activ, observabil, pe aceeași rută/incarnation și prezent în ambele observații, cu deplasare compatibilă; ocuparea/previunea sa la acel moment trebuie să suprapună intervalul subjectului cu gapul configurat. Nu se interpolează prin teleport, tick lipsă, acoperire necunoscută ori actor nou. Dovezile sunt context fizic, nu verdict de încălcare. Evaluarea/gapurile descriu observația curentă; o traversare swept poate produce dovadă istorică chiar dacă statusul curent este NO_EXPOSURE deoarece subjectul este deja CLEARED.

Repetarea identică în același tick nu reemite dovezi; o repetare conflictuală și tick-urile stale sunt respinse înainte de mutația istoricului. Istoria per vehicul, incarnation și epoch nu moștenește hold de la o entitate înlocuită. `forgetVehicle` elimină istoricul live și păstrează tombstone-ul de incarnation; `advanceWorldEpoch(next)` strict crescător resetează istorii/tombstones. `dispose()` este idempotent, golește resursele dinamice și respinge observe/forget/reset ulterior. Politica și geometria statică bounded rămân readonly accesibile până când ownerul elimină controllerul. Modulul nu deține timers, RAF, listeners, bus, cozi sau ledger de evenimente.

Capacitățile implicite sunt128 vehicule live,4096 identități per epoch,128 actori traffic/observație,4096 datums total/observație (max128/actor),65536 code units pentru fiecare fingerprint canonic. Limitele sunt verificate înainte de a păstra o observație; nu există LRU care redeschide incarnations. Fingerprinturile au o limită derivată aggregate: implicit128×65536 code units, adică până la16MiB payload UTF-16; configurarea maximă512×131072 permite128MiB. Acest plafon nu este heap măsurat: se adaugă string/object overhead, subjectul, gapurile bounded și max4096 identități implicit (max100000 configurabil, fiecare ID≤256 caractere). Tombstone-ul este un JSON key cu două IDs: escapingul poate extinde conservator payloadul la3079 code units/identitate, până la aproximativ24,1MiB UTF-16 implicit sau587,3MiB la100000identități configurate, înainte de overhead. Aceste maxime configurabile nu sunt recomandări de preset și nu există plafon aggregate separat mai mic decât produsul capacităților. `getStats()` arată contoare și code units agregate, nu RAM exact. Callerul trebuie să aleagă limitele după traficul real; amprenta completă bounded este necesară pentru respingerea repetărilor conflictuale și reconstrucția rară a traversării.

Pragurile de gap, hold, viteză și continuitate sunt provizorii și necesită calibrare cu fizica/trafficul viitor. Nu există încă trafic live în aplicație; verificarea folosește observații sintetice explicite și fixture CROSS/T geometric035. [Dovezile038](Evidence/038-priority-rules/report.md) separă baseline-ul comparabil, costul suplimentar, overheadul observatorului și limitele. Nu sunt afirmații de FPS, GPU, playtest ori certificare de driving.
