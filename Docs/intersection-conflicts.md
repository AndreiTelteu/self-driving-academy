# Mișcări și conflicte în intersecții (PBI035)

`createIntersectionConflicts(map, { heightToleranceM? })` parsează și copiază harta validată032, apoi construiește relațiile dintre mișcările permise din fiecare intersecție. Nu citește meshuri, materiale, texturi sau semafoare runtime. IDs și geometria declarată sunt autoritatea. Nu creează mișcări noi și nu atribuie prioritate, încălcări sau eligibilitate pentru learning.

`getMovement(intersectionId, movementId)` oferă mișcarea semantică și traiectoria orientată. `getZones(intersectionId)` oferă zonele authored cu polygon în metri și mișcările care le declară. `getRelation(intersectionId, a, b)` oferă o pereche canonică, cu ID stabil și simetric, incompatibilitate, motive separate, IDs de zone comune și primul witness geometric (segmente, poziții și distanța centerline). `getIncompatible` întoarce vecinii incompatibili precomputați. IDs necunoscute sau perechea unei mișcări cu ea însăși dau null/listă goală; o relație cunoscută compatibilă este explicit `incompatible:false`. Nu se compară mișcări din intersecții diferite.

Motivele semantice sunt SHARED_ZONE, SHARED_ENTRY și SHARED_EXIT. O zonă declarată comună sau aceeași intrare/ieșire impune incompatibilitate de ocupare chiar dacă centerlines nu se intersectează; aceasta este o restricție conservatoare de hartă, nu o prioritate. Geometria este evaluată independent, inclusiv când authoringul nu declară o zonă comună: TRAJECTORY_ENVELOPES raportează apropierea corridorurilor traversate. Lipsa declarației nu ascunde o traversare geometrică. Un consumator de semafoare viitor trebuie să verifice și aceste relații geometrice înainte de permiterea simultană;035 nu modifică validatorul032 sau programul semafoarelor.

Corridorul fiecărei mișcări folosește jumătate din maximul lățimii benzii de intrare/ieșire. Perechile de segmente X/Z sunt incompatibile dacă distanța minimă este cel mult suma celor două jumătăți, inclusiv tangentă/collinear overlap. Prima pereche de segmente găsită oferă witnessul, nu toate punctele și nici o estimare de footprint al unui vehicul. Intervalele de înălțime ale segmentelor trebuie să se suprapună cu toleranța verticală implicit1,5m, configurabil0..100m. Astfel un pod separat nu creează conflict geometric. Folosirea intervalelor întregului segment și a corridorului maxim este conservatoare: pe rampe sau la schimbări de lățime poate produce false positive. Nu promite narrow-phase3D, vehicule orientate, temporal overlap sau turn-radius validation. Geometria polyline authored este contractul actual.

Construirea este pentru încărcarea hărții, nu pentru fiecare tick. Maximum65536relații de perechi per hartă este verificat înaintea lucrului geometric; maximum2.000.000comparații de segmente oprește construirea cu eroare explicită și instrucțiune de simplificare. Nu se trunchiază perechi relevante. Limitele032 (256intersecții,128mișcări/128zone per intersecție,65536total array entries) rămân valabile. Traiectoriile și poligoanele readonly sunt reutilizate per geometryId, pentru a nu multiplica un path mare la fiecare referință. `getStats()` expune relații, mișcări, zone, comparații și numărul geometriilor unice. Query-urile sunt lookup-uri în structuri private plafonate; nu au cache care crește după construcție. Cheile scurte sunt alocări temporare; nu pretindem zeroalocări sau RAM exactă.

Fixture-urile T/cruce verifică traversări, mișcări paralele opuse, viraje separate, merge și zone semantice independente. Testele negative verifică date invalide, bugetele, shared geometry și copii readonly. [Dovezi și costuri](Evidence/035-intersection-conflicts/report.md) separă baseline-ul existent, costul construcției și query-urilor noi, observatorul bounded și ciclurile GC. Acesta este un modul CPU pur; nu adaugă încă UI, meshuri sau query-uri în gameplay.
